# Provider artifacts

> Consulted from `rules/mapping-variables-and-logic.md` ("Provider artifacts"). Source templates carry provider-specific machinery that must not be copied verbatim.

| Artifact | Examples | Handling |
| -------- | -------- | -------- |
| Unsubscribe links | SendGrid `<%asm_group_unsubscribe_raw_url%>`, `{{{unsubscribe}}}`; Mailchimp `*|UNSUB|*`; Mailgun `%unsubscribe_url%` | ❓ checkpoint item. Options: Knock hosted commercial unsubscribe (`{{ vars.commercial_unsubscribe_url }}`), the customer's own preference-center URL, or provider-injected unsubscribe if their provider config adds it. Never drop the link from commercial emails — CAN-SPAM/GDPR. |
| Open-tracking pixels | 1x1 `<img>` beacons | Strip. Tracking is configured on the Knock channel/provider (`open_tracking`/`link_tracking` settings), which re-injects as needed. |
| Click-tracking wrappers | Rewritten hrefs through provider domains | Restore the original destination URL; provider-level link tracking re-wraps at send. |
| UTM parameters | `?utm_source=mailgun&utm_campaign=…` | Preserve **verbatim** by default; flag stale values (e.g. `utm_source=mailgun` after moving senders) as a ❓ suggestion, don't silently rewrite. Malformed encodings (`%%20`, raw spaces, an unbalanced quote inside a query string) are also preserved verbatim and flagged `❓default` with the corrected form proposed. |
| Preference/profile links | `*|UPDATE_PROFILE|*` | ❓ — map to the customer's preference center (Knock hosted or their own). |
| Customer's own preference-center URL passed as a template variable | `{{unsubscribe_url}}`, `{{notification_settings_url}}`, a composed `{{origin}}/org/{{org_id}}/settings/notifications` | Keep it on `data.*` — it is the customer's contract, not a provider artifact. When one chrome family delivers it several ways, unify in the layout with a Liquid fallback chain (`{% if data.unsubscribe_url %}…{% else %}{{ vars.app_url }}/org/{{ data.org_id }}/…{% endif %}`) rather than inventing a new field. Knock's own alternatives — `{{ vars.manage_preferences_url }}` for the [hosted preference center](https://docs.knock.app/preferences/hosted-preference-center) and `{{ vars.commercial_unsubscribe_url }}` for [commercial unsubscribe](https://docs.knock.app/preferences/commercial-unsubscribe) — need those features configured in the account (a preference center enabled; the workflow marked commercial). A customer doing an initial migration usually has neither yet, so propose them as a `❓fyi` follow-up, not as the migration default. |
| No unsubscribe or preference link at all in the source | (absent) | Record it as `❓fyi` with a transactional/commercial classification of the template. Never add a link silently: transactional emails need none; a commercial email should get Knock's commercial unsubscribe (link above), which is a workflow setting plus a footer link, once the customer enables it. |
| View-in-browser links | `*|ARCHIVE|*`, `<%webversion%>` | ❓ — Knock has no hosted web version; usually dropped with user confirmation. |
| Inline images by content-id | `<img src="cid:{{image_cid}}">` (MIME attachment referenced inline) | `❓blocking` either way, because it changes what the trigger sends. Knock supports inline images by content-id on **SendGrid, Postmark, and Resend** ([email attachments](https://docs.knock.app/integrations/email/attachments)): keep `<img src="cid:<id>">` in an `html` block or in partial content, and have the trigger send the file as an attachment object with `content_id` and `disposition: "inline"` under `data.attachments` (or the step's `attachment_key`). On other providers (Mailgun, SES, …) the image must be hosted and referenced by URL — an `image` block at template level (it takes a hosted URL, an account asset, or a dashboard upload) or an `<img>` inside partial content when it repeats per item. Dashboard previews cannot show inline attachments, so verify with a test send. |
| Provider template metadata | SendGrid categories, custom args | Only if needed: `channel_overrides.json_overrides` on the email step. |
